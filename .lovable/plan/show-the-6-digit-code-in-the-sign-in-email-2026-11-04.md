# Show the 6-digit code in the sign-in email

## Answers

1. **How templates are configured today.** No custom templates exist. There is no `auth-email-hook` function, no `_shared/email-templates/`, and no email sender domain on this project (status: not_started). Every auth email uses Lovable's built-in default templates. You can't edit these default templates in a dashboard. The only supported way to change one is the managed custom-template setup: Lovable generates six templates plus an `auth-email-hook` function, and we then edit only the magic-link template.

2. **Domain or secrets.** You need a custom sending domain that you own (for example `notify.drivepilot.app`), added through the email setup dialog with its DNS records verified. Custom templates are only used once that domain is verified. Until then, the current default emails keep going out. No new secrets are needed because Lovable provisions the key itself. Custom-domain email requires a paid plan.

3. **Effect on other emails.** The setup creates all six templates at once (signup, magic link, recovery, invite, email change, reauthentication), and they all start sending from your domain. I'll only change the wording and layout of `magic-link.tsx`. The other five stay as generated: plain, with the same content as today's defaults. They'll just come from your domain with neutral styling. If you'd rather they match DrivePilot's look too, say so. Otherwise I'll leave them alone.

4. **Exactly what changes.**
   - Setting (you do this): add the sender domain via the setup dialog, then add the DNS records.
   - Generated by the managed tools, not hand-written:
     - `supabase/functions/auth-email-hook/index.ts` and `deno.json`
     - `supabase/functions/_shared/email-templates/*.tsx`
     - the function entry in `supabase/config.toml`
     - the email queue setup
   - Edited by hand, only `supabase/functions/_shared/email-templates/magic-link.tsx`:
     - the code shown large in a monospace font with letter spacing, so it's easy to select and copy
     - one line: "Enter this code on the DrivePilot sign-in page. It expires in 1 hour."
     - below that, a small link: "Or click here to sign in" (the existing sign-in link)
   - Deploy `auth-email-hook`.
   - No changes to `/auth`, `request-login-code`, the verify step, or the database.

## Steps

1. You open the setup dialog and add the domain.
2. I set up the email infrastructure, generate the templates, edit the magic-link template, and deploy the hook.
3. Once DNS verifies (shown in More → Emails), the new email goes live. I'll check it with the magic-link preview and a test send.

## Caveats

- Code lifetime is the hosted "Email OTP expiration" setting (More → Users → Auth settings → Email). The "1 hour" wording is only correct if that setting is 3600 seconds. Please confirm it, or I'll word the line from whatever value it has.
- The template uses the code variable the hook passes in. If the scaffolded magic-link payload doesn't include the code, I'll stop and tell you before making any workaround.
